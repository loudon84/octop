## Root 四项具名冻结修正（独立规划复审输入）

1. Scoped patch 精确目标：现有 chatStore.patchToolResultData(callId,nextData) 全局 fallback 保持供旧 caller 使用；最小扩展第三可选参数 targetSessionId:string，并返回是否实际 patch 的 boolean（旧 caller 可忽略返回）。提供第三参数时只在该 session 调用同一现有 tryPatch 算法，缺 row 返回 false，绝不搜索 focused 或其它 session；不复制合并算法、不重写 store。新 tool Host 只传捕获非空 thread，false 时固定 inactive/error；caller 亦检查该工具仍存在。测试同 callId 两线程、目标消失时其它线程不被 patch；原两参旧行为保留。新增 chatStore 源码和专用测试已先列白名单，无后端协议变化。
2. 不采用可复活的动态 active lease。仅 toolUi renderer 在隐藏/非活动时真正卸载，重新激活新建 Host；其它 file/browser/terminal keepalive 保持。当前 openTabs 经 scope 同步过滤后直接映射工具内容，不使用 mountedToolUiCallIds 的旧 effect 缓存。旧 Host 一次失效永久失效，即使同 scope 重开；旧 promise success/reject 迟到均不能发布。presentation.active 在已卸载前为 false 或由一次性 mount liveness 保证，P09b 不依赖跨激活正文/连续游标缓存。
3. Plugin 的无 tool binding Host（setup registration/surface/createPluginUiHost）不得通过 global dock handlers 创建、激活或关闭 scoped tool tab；open/close 固定拒绝，不从 opts/currentglobalcontext 合成 scope/owner/returnFocus。旧 renderer 的 props/interface保持兼容，ToolDetailsInline 同样给旧插件 renderer 注入新 scoped props.host；其正确调用 props.host.open/close 可用。捕获 setup Host 来控制工具的旧插件需改用 props.host，此处不保留无来源能力作为兼容后门；root裁决依据本次已规定的当前工具所有权，代价为该错误调用模式需迁移，最终审查须见此兼容说明。builtin 既有内部全局 Host 可沿现有接线，不能借 plugin-controlled options 冒充 builtin。注册/设置 UI 不获得工具 binding。源 ToolDetailsInline 通用按钮直接用自身内部 binding，与 plugin props 同一可信入口；全局 plugin入口不造 tab。
4. source稳定外层 group 持有独立 ref，renderer/placeholder 都是同一父壳子内容；useToolUiDockButtonStyle 的 wrapRef 继续在内层 renderer 容器，不挪到外壳。如需样式仅 chatMessages.partial.less。焦点 callback 不在 state updater 运行，只在 close 后 inline 恢复提交且当前同 scope/DOMconnected 时一次执行。

补充实际作用域：ToolDetailsInline 的 agentId 可能是团队 speakerAgentId，不得用作 API 目标；必须取 Chat provider 的 resolvedAgentId+activeThreadId。当前 registration 判断同时要求 listRegisteredRenderers().includes(registration) 与 actual resolve 仍等于该对象，避免旧 byToolName 缓存假活。JSON state 必须区分属性缺省与显式 undefined（后者拒绝），复制后原对象变更不影响 tab。以上均纳入实际 caller 集成回归。

同步 presentation 约束：控制器在关闭 dock、切换 tab（含非工具 tab）、inline 打开 dock、同 call 重新打开/替换 state 的事件处理调用栈中，先使即将隐藏/被替换的实际 binding 失活（写其当前 liveness/activation ref），然后提交 React 更新和卸载。不等待 cleanup/effect/下一次 render 才失活；每次重新激活创建新一次性 binding，旧 binding 永不复活。沿已有 tool tab/provider 的局部 binding 实现，不增加全局 registry。真实 caller 测试必须在触发上述事件后、React 提交前立即尝试旧 Host request/open/close/patch，并在隐藏→重开后结算旧 success/reject，均不得操作或发布；layout模式改变本身若仍可见不需撤销其它文件/browser/terminal状态。

同 call 替换 state 明确属于新 activation：必须改变该 toolUi reader 的一次性内部 activation/binding 身份，并据此强制 reader 重挂载；不能继续只用 callId 作 React key。Host memo 同样包含该 activation 身份。新 reader 收到复制后的新 state 并拥有新 Host，旧 Host 永不复活；同 call 第二次选择的真实 caller 测试同时断言新 Host 可操作、旧 Host 不可操作、旧请求迟到不发布。内部 activation 仅现有临时 tab 元数据，不是认证 epoch、持久ID或新注册表。
